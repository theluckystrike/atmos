## Usage

```shell
atmos aws cloudformation source <subcommand> [options]
```

## Examples

### Vendor a Component

```shell
atmos aws cloudformation source pull vpc --stack dev
```

### Force Re-vendor

Refresh the configured source, even if its directory exists:

```shell
atmos aws cloudformation source pull vpc --stack dev --force
```

Update the URI or version in stack configuration to download a different revision.

### View Source Configuration

```shell
atmos aws cloudformation source describe vpc --stack dev
```

### List Components with Sources

```shell
atmos aws cloudformation source list --stack dev
```

### Delete Vendored Source

```shell
atmos aws cloudformation source delete vpc --stack dev --force
```

## Arguments

<dl>
  <dt>`component`</dt>
  <dd>Component to pull, describe, or delete. With `list`, optionally filters results
  to a component. See each subcommand for interactive selection behavior.</dd>
</dl>

## Flags

<dl>
  <dt>`--stack`, `-s`</dt>
  <dd>Atmos stack. Also configurable with `ATMOS_STACK`. The `list` command
  searches all stacks when this is omitted.</dd>

  <dt>`--identity`, `-i`</dt>
  <dd>Identity for authenticated source downloads.</dd>

  <dt>`--force`, `-f`</dt>
  <dd>Refresh an existing source with `pull`, or confirm removal with `delete`.</dd>

  <dt>`--dry-run`</dt>
  <dd>Preview a pull or deletion without authentication, downloads, or deletion.</dd>
</dl>

## Automatic Provisioning

Commands that need template files download their configured source before use.
For example, the first `plan` downloads a missing source:

```shell
atmos aws cloudformation plan vpc --stack dev
```

Deployed-stack reads and stack deletion do not need a source download.
Named changeset execution may need source files for a configured stack policy.
Dry-run never downloads sources.

## CLI Commands

Use `pull --force` for an explicit refresh, `describe` to inspect configuration,
`list` to find configured sources, and `delete` to remove a download.

## How It Works

1. Resolve the component's source and destination.
2. Download the source when a refresh is needed.
3. Apply inclusion and exclusion filters.
4. Make the downloaded files available to the component.

See [caching and refresh](/stacks/components/aws-cloudformation#caching-and-refresh)
for URI, version, and TTL handling.

## Source Specification

### String Format (Simple)

```yaml
source: github.com/acme/cfn-templates.git//vpc?ref=1.2.0
```

### Map Format (Full Control)

```yaml
source:
  uri: github.com/acme/cfn-templates.git//vpc
  version: 1.2.0
  included_paths:
    - "*.yaml"
  excluded_paths:
    - "tests/**"
```

### Source Fields

See the [source field reference](/stacks/components/aws-cloudformation#source-fields)
for URI, version, filters, TTL, and retry settings.

## Authentication

### Component-Level Identity

Downloads use the component's resolved identity. Configure it through
[Atmos Auth](/stacks/auth). For private buckets, use an authenticated
[S3 source URI](/stacks/components/aws-cloudformation#private-s3-sources).

### Identity Flag Override

```shell
atmos aws cloudformation source pull vpc --stack dev --identity admin
```

## Configuration Patterns

### Inheritance with source

Declare a source in a catalog component and inherit it in each stack. See
[source-based version pinning](/design-patterns/version-management/source-based-versioning).

### Version Override per Environment

Override `source.version` in the environment's stack to select a different Git
revision. Use a workdir when instances need separate downloaded sources.
See [Workdirs](/stacks/components/aws-cloudformation#workdirs).

## Supported Source Types

### Git Sources

```yaml
source:
  uri: git::https://github.com/acme/cfn-templates.git//vpc
  version: 1.2.0
```

For SSH, use `git::ssh://git@github.com/acme/cfn-templates.git//vpc`.

### S3 Sources

```yaml
source:
  uri: s3://my-cfn-templates/vpc.yaml?region=us-east-1
```

### HTTP/HTTPS Sources

```yaml
source:
  uri: https://releases.example.com/templates/vpc-1.2.0.tar.gz
```

### OCI Registry Sources

```yaml
source:
  uri: oci::registry.example.com/templates/vpc:1.2.0
```
